# CPU PUCT evaluation-cost experiment

This follow-up keeps the Betawi rules, both compact trained models and PUCT mathematics fixed. It tests native CPU strength and removes repeated evaluation work before any larger training campaign. The prior Phase 6 acceptance's 1,192 input files, including all 878 Stage 5 inputs, remain immutable.

The six candidates are warm and updated models, each using the original double-pass native adapter, a structured single-pass adapter without caching, and that same single-pass adapter with a 4,096-entry LRU. The cache belongs to one evaluator/model and uses all sixteen input cells plus the input controller. It neither merges store offsets nor shares entries between models. Returned predictions are copies. Every decision clears the cache inside its whole clock; only the remaining positive integer milliseconds are granted to frozen PUCT. A remaining budget below one millisecond produces a counted unusable recommendation, never an unlimited search.

The predeclared comparison uses the same 80 development positions at 25/100 ms and the same 24 development arena families, paired seats and 25 ms decisions against H_v1 and H8 relay CPU. Twelve comparisons produce 576 games. Family order rotates the comparisons and alternates seat order to balance timing drift. All variants are reported. These reused families are not unseen release validation, and the twelve 95% intervals are exploratory without multiple-comparison adjustment.

The cost sweep contains six startup units, 36 parity units, 504 microbenchmark units and 864 real fixed-tree units: 1,410 total. Seven blocks test batch sizes 1/2/4/8/16/32 with 64 repetitions. Empty-cache calls include reset time; models are already loaded/warmed. Hot-cache calls prefill all 48 roots outside their clocks and measure retrieval's ceiling, not realistic tree throughput. Three blocks compare 64-backup trees on all 48 current H8 development roots, with exact move/visit/value agreement required across evaluators for each model.

The predeclared cost gate requires the median matched single-pass/legacy whole-tree ratio to be below one for both models, after taking each root's three-block median. Single-pass fixed-tree feature simulations and deposits must be exactly half the legacy work. Cache gains are descriptive and may vary by workload. Physical forwards, cache events and feature work are separate from frozen PUCT's logical row-evaluation counter. Startup, preflight, process peaks, journal costs and deadline overshoot have explicit scopes. Electricity is not measured.

Producer sources and build/model identities are frozen in `build/puct-cpu-implementation.json`. Review fixes before production preserve earlier fixture manifests and diagnostics. Once a production journal exists, source refresh is refused; a changed producer needs a new experiment. Journals commit completed cost units, position cases and arena games. The analyzer preserves its previous completed recommendation while unfinished tree work is recomputed. Real process kills, corrupt-state refusals and completed byte/mtime stability must pass independent audit.

No training, new targets, larger model, automatic default promotion, sealed-target access or full-game solving is part of this experiment. Strength and engineering acceptance remain separate. H_v1 stays the default. Fresh release validation, broader replay diversity, typed exact lookup, unified analysis and reproducible packaging remain required work for the finished analyzer.
