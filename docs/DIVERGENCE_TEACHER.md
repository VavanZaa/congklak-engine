# Five-root diagnostic teacher labels

The exact five H_v1 first-divergence states from the sealed ordinary-value loss review are diagnostic only. The inner teacher root is the exact already-frozen row from `build/divergence-panel.json`; `source_root_sha256` binds that row, and the new outer wrapper has its own hash. Raw pits, stores, controller, source seat/divergence hashes and old actions remain unchanged. No quotient, player swap or store-offset action-Q reuse is allowed.

Before any production teacher call, the fixed-simulation study must be genuinely closed: its strict CPU-only primary witness binds all 40 completed cells. Current passed independent preflight and production-search proof groups must also cover their exact declared methods, with every recorded source hash current. Runtime identity binds these proof file hashes. The teacher plan and implementation freeze before those outcomes and do not select roots or budgets from the comparison results.

Attempt every root at requested H8, H10 and H12, independently of earlier completion. Node caps are respectively 2, 5 and 10 million per root, with a maximum 85 million requested nodes for all 15 production attempts. Use the existing H_v1 native teacher, PVS, 16 MiB TT, 512 MiB memory and no time deadline. There is no automatic budget expansion. Each completed iteration is retained in the attempt history as a consecutive prefix; each auxiliary report retains its actual depth. Only complete requested-depth full-action-Q reports enter the corresponding label table. Capped attempts remain explicit missing requested references, with all returned history and physical work retained. Finite horizon estimates are not solved-game truth.

New versioned FULL/WAL SQLite transactions commit an entire root-stage attempt, its returned completed iteration history and optional full requested label together. An interrupted uncommitted search is recomputed; committed attempts never rerun. Same-depth full action-Q and best sets must agree across completed reports from independent horizon attempts. Values and best moves need not be monotone with depth. Cancellation preserves native token registration to interrupt active search.

`run(path, stage='all', fixture=False, roots=None, on_event=None, cancel=None)` resumes the journal. `load_rows(path)` returns `(roots, stores, manifest)` through a strict read-only validator. Tables are `roots` and `h8_attempts`, `h8_labels`, `h10_attempts`, `h10_labels`, `h12_attempts`, `h12_labels`, each with `(state, body, hash)`. A pure completed-marker validation runs before any publication or missing-export repair. CPU-only completed readers perform no teacher calls, Torch imports or training, and repeated completed invocations retain durable bytes and mtimes.

The CLI exposes `plan`, `freeze`, `h8`, `h10`, `h12`, `all` and read-only `verify`. Flushed pre/post-commit events include stage, raw state key, status, requested target count and aggregate committed-attempt prefix. `DIVERGENCE_TEACHER_BLOCK_EVENT`, `DIVERGENCE_TEACHER_BLOCK_STEP`, and `DIVERGENCE_TEACHER_MARKER` provide real subprocess kill barriers.

Engineering fixtures use only the first two already-consumed diagnostic roots from the previous midgame label journal, at explicitly different depths 2/3/4. Every public fixture call also requires the source implementation freeze and binds its actual hash; it skips only the production outcome/audit gate. Fixtures remain inside `build` and cannot substitute for production labels. No new panel search, training, game, weight change or model promotion is authorized by these fixtures.

One additional one-node engineering call on an already-consumed fixture root retains an actual partial attempt solely to test admission refusal. Its separate fixture evidence records the changed cap; it is never inserted into a completed study label table or counted in production work.
