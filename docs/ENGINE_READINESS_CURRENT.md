# Engine readiness after the small value pilot

The collection/training infrastructure is ready for a **larger, bounded data experiment**. The evidence does not yet justify a blind 100,000-position labeling campaign or a long training run. The current command-line analyzer is usable for internal position analysis; a finished, demonstrably strong analyzer is not release-ready.

These are separate judgments. Recovery and correctness checks establish that work can be saved and reproduced. Playing tests establish whether the resulting evaluator/search is useful. More rows or optimizer draws alone do not satisfy the quality gate. There is no defensible single completion percentage or release date from the present evidence.

| Area | Readiness | What remains |
| --- | --- | --- |
| Declared Betawi rules, simulator, CPU analysis | Implemented and audited; usable locally | Keep the precise seven-pit, single-round seed-margin profile visible. Other conventions are separate versions. |
| Data generation, ownership, weighting, checkpoints | Ready for bounded expansion | Predeclare new histories, target types, per-root budgets, exclusions, quotas and stopping rules; retain rare mechanisms and provenance. |
| Ordinary-position coverage | Still small and uneven | The recent optimizer addition is 61 roots from 59 assigned families. Improve natural midgame coverage using measured failure categories; record genuine shortfalls rather than inventing quota filler. |
| Teacher-target reliability | Partial | Six selected disagreements have H14 labels, including five training roots. They remain finite-horizon estimates; agreement and label depth are not correctness certificates. |
| Learned playing strength | Open gate | The latest pilot improves aggregate teacher fit but slightly worsens ordinary validation and does not beat both CPU baselines reliably. Keep the existing control and H_v1 default. |
| Exact memory | Verified K<=4, explicit separate lookup | Consolidate lookup with the product's result types and mode selection. Covered exact facts and uncovered estimates must remain distinct. Interior search lookup requires its own declared recurrence and validation. |
| Analysis interface | Working CLI and separate experimental tools | Consolidate backend/model selection, move rankings, continuations, explanations and cancellation/resume. The main NDJSON request currently has no model/backend selector. |
| Validation and release | Not demonstrated for a frozen product | Use fresh protected development families to select a release candidate, then characterize that frozen release on the sealed test without tuning it from those results. Package and test installation, runtime limits, rollback and clean-machine operation. |

The 9,000-root H8 corpus, earlier pilot data, later target replacements and repeated optimizer draws must not be added together as independent observations. The latest run admitted 7,624 optimizer roots: 7,563 replay roots and 61 newer ordinary roots. Its 51,200 draws are replacement exposure. Fourteen ordinary validation roots and eight protected diagnostic roots were excluded from new optimization, but their results are now consumed development evidence. Existing model ancestry and shared history prefixes are not erased by new exclusion filters.

The recent natural pool supplied no strict ordinary roots in the 75-98 active-seed band. This does not mean early-game states are absent or unimportant: the strict classifier requires every legal move to avoid capture, bonus and pass mechanisms. New collection should measure actual opening/midgame mechanisms and natural frequency rather than force an artificial early-ordinary quota. Assigned family IDs and feature distance do not prove independent gameplay diversity.

For a next data experiment, choose a modest, versioned slice from legal recorded histories and declared opponents/openings. Use the [ordinary-error review](../build/pilot-loss-review-ordinary.json) and [saved arena review](../build/pilot-loss-review-arena.json) to choose coverage questions. Keep training, validation and diagnostics separated before labeling; retain full action targets, complete-depth status and target provenance. Predeclare how target instability affects exposure. Compare a fixed candidate against the unchanged control and both baselines before increasing the next budget. This recommendation does not start collection or training.

The next collector must explicitly extend its role-aware protection ledger with the latest 144 pilot game trajectories and reviewed evaluation roots before selection. Preserve the 83 newer roots' existing ownership: 61 training candidates may remain eligible for rehearsal, while 14 validation and 8 diagnostic roots remain excluded. Retain the original development-root ownership, including the 259 ordinary development rows, and resolve family/quotient cross-cohort collisions before admission. Preserving artifact hashes alone does not enforce those future exclusions. Current ordinary-history campaigns use single-writer SQLite chunks; a new sharded loader or parallel generation path would need its own implementation and throughput checks before claiming scale readiness.

For the first product, a board editor or play client is an optional scope choice. A trustworthy local CLI can be a product without a graphical board, but it still needs a selected supported backend, documented limitations, consistent estimate/proof labels and reproducible distribution. The current setup documents Windows/Python/Visual Studio tools and reuses a machine-specific training environment; a clean-machine release has not been established.

Roadmap stages 0-4 have their working foundations. Stage 5 has learned CPU experiments but the planned broad 100,000-position campaign and release-validation gate remain unfinished. Stage 6 has policy training, PUCT, self-play and recovery implementations; its stronger-challenger gate remains open. Root proof certificates and larger-domain solving are stages 7-8, later objectives rather than prerequisites for a useful position analyzer. K=4 covers only states with at most four active seeds; it does not solve the 98-seed opening.

The current recommendation is to keep the policy/model and default fixed while completing this diagnosis, then authorize a narrowly defined data or learning experiment based on its evidence. Do not enlarge the model, replay pool or training duration merely because the pipeline can run longer. No new strength, generalization or energy result is established by this readiness review.
