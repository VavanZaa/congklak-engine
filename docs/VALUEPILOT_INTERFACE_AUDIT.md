# Value-branch interface and reservation audit

The pre-training implementation passed independent acceptance. **The pilot is not ready to train:** the existing development pool contains **zero eligible ordinary arena components**, while the accepted plan requires eight. The reservation publisher therefore commits a recoverable, certified **HOLD**, with no partial training, fit-check or arena memberships. Production model initialization refuses that HOLD. No optimizer steps, training draws, new teacher labels or new games ran. H_v1 remains the default.

The full metadata graph contains 21,041 components, including isolated protected-family/quotient tombstones. It connects 9,667 source-origin observations and protects the actual trajectories reconstructed from 2,400 historical games, with 77,121 literal transitions. These are replays of saved actions, not new searches or self-play. The independent audit checked 9,999 origin references, including the 332 diagnostic-panel records. Eligible optimizer support can fill 640 training/fit slots, but it is deliberately not reserved separately from the failed joint arena assignment. The remaining arena pools contain 90 capture components and 49 bonus components; they cannot replace ordinary positions.

The new export, loader and native evaluator preserve all eight original tensors, including the policy and original value head. The separate 2,065-parameter branch starts with zero output, uses the existing 127 inputs, and is called only with 25–74 active seeds. Other positions call the frozen value path directly. Model identities bind the branch, base export, gate, rules, encoder, actual improved PUCT protocol, input manifest, sources and native build. Engineering exports are marked ineligible for training. No production value export was created.

Independent conformance used all 7,513 eligible existing H8 source roots and 32 boundary/forced-pass fixtures, without reading their H8 targets. These are engineering test inputs, not 7,513 new reservations or unseen validation. Both scalar and AVX2 native backends preserved control policy logits bit for bit, including a synthetic nonzero branch. The zero branch reproduced control values exactly. Native versus independent float64 algebra differed by at most `5.6844e-14` seeds and `3.5528e-15` logits; scale-256 scores agreed exactly. CPU FP32 errors were at most `1.8441e-5` seeds, `8.2921e-7` logits and one score unit, within the previously fixed limits. The isolated generator matched the declared initialization. All 2,065 synthetic branch derivatives matched the analytic formula; central differences also checked a coordinate from each of A, b, v and c. CUDA was not initialized.

Sixteen improved-PUCT searches on eight low-active roots requested 128 backups each. Control and the synthetic nonzero branch agreed exactly on actions, visits, Q values and physical search/feature counts, excluding clocks. This verifies the low-active bypass contract. It is not an equal-time strength test. The planned H_v1/H8 relay comparisons and endgame strength guard remain future work after admission and training.

Six recovery boundaries passed real process-kill tests: before/after reservation catalog commit, before/after model commit, and before/after initialization-certificate commit. Every committed prefix preserved bytes, sizes and modification times. Once model bytes were committed, recovery completed with the default interpreter, which has no Torch installation. Completed API and CLI routes ran with writer, inventory producer, encoder, forward, search and Torch-import entrypoints trapped. Required missing/corrupt evidence refused instead of recomputing. Validly rehashed schema, gate, search, build, input, encoder, rule, tensor and base-policy mutations were rejected. A fully rehashed nonzero branch could not be certified as step zero. All 5,627 previously accepted inputs remained unchanged.

The accepted audit has six substantive methods: five from the original executed source and the repaired recovery method from a separate v2 harness. There were seven method executions in total. The first recovery method passed both data-kill cases, then failed because its harness assumed that a Windows virtual-environment launcher PID equaled the Python worker PID. That failed report, source, logs and fixtures remain retained. The v2 harness verifies script identity and parent lineage and terminates the actual worker through a Windows process handle. Its six kills passed; together with the earlier two data repeats, eight protocol kills are recorded. The failed launch was cleaned up separately and was not counted as a successful recovery case; its launcher PID was not retained, and the audit does not invent one. No orphan export worker remained.

The dashboard distinguishes accepted engineering work from training readiness, reports zero committed optimizer/fit/arena memberships and zero production value exports, and retains the ordinary-position HOLD. Completed snapshots are read-only and reject stale observer sources, changed bound evidence and nonzero pre-training execution counters. Verification used the backend and OS listener; no browser or HTTP inspection was performed.

The next work is to specify and generate separate ordinary development starts with enough distinct full components, protect their complete origin closure, then rerun joint admission and conformance on the actual selected corpus. Eight usable components is the minimum accepted quota; the collection should allow for exclusions. This audit does not authorize lowering the quota, reusing consumed cases, changing the fixed policy, starting training or promoting a model. Optimizer-state/RNG recovery and decision/game recovery remain checks for their future implementations.
