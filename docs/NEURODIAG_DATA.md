# Neurodiag data admission and packaging

`congklak/neurodiag_data.py` owns metadata admission, deterministic panel selection and one-time existing-target/feature packaging for `NEURODIAG_SCOPE.md`. It never imports an engine runtime or computes a model output. Models remain the control quality export and fixed ordinary-value candidate. This is a training-source diagnostic: historical roles persist and no new optimization reservation is created.

## Files and public API

| API | Contract |
|---|---|
| `metadata_inventory()` | Narrow root/state/role projections and keys/hashes; returns complete component membership, blocked reasons and clean source pools |
| `select(inventory)` | Deterministic 256-root eight-cell matching, plus all 28 clean H8/H10 pairs and 48 initial return records |
| `prepare()` | Immutable `build/neurodiag-inventory.json` and `build/neurodiag-panel.json`, without selected target/feature resolution |
| `resolve_inputs(panel=None)` | Frozen panel/source required; selected admitted targets and exact caches only, plus declared 13 literal vectors/15 comparisons |
| `validate_inputs(pack, panel=None)` | Source/shape/hash/metadata ownership checks without target reloading, encoder, forward, derivatives or SVD |
| `load_inputs()` | Read and structurally validate `build/neurodiag-inputs.json` |

The parent workflow is `congklak/neurodiag.py` and `tools/diagnose-neural.py`. Its plan/implementation/source-freeze bind this module, owner suite, helper, accepted encoder specification, scope and retained exploration provenance. Inputs are published afterward and their actual immutable SHA is bound by each journal identity and the independent observation certificate, avoiding a circular source freeze.

## Whole-component eligibility

Admission starts with all accepted ancestral stratum component bodies. It unions all 9,000 deeper-corpus root metadata origins (training and development), all declared eligible candidates from 512 ordinary self-play history families, and both accepted replay metadata pools. Every duplicate origin family is retained in the graph. Entire component blocking propagates inherited blocked reasons, actual development/validation ownership, protected root/trajectory quotients/families, prior H12/H14 exposure and all allocation/stratum/qstability reservations. The true-evaluation ledgers are distinguished from metadata-only novelty reservations. A prior training observation is not itself an evaluation ban.

All source file SHAs are checked against the new prior baseline before extracting metadata. Quotients ignore store offsets and identify player swaps solely for protection closure. Raw state, actor, legal mask and target ownership remain unchanged. Missing source family graph membership refuses explicitly. The inventory retains every component's full family/quotient support, reasons and ancestral component IDs, including late active-five aliases. This supports independent reconstruction rather than trusting a small selected-row whitelist.

The clean primary pool is 7,513 H8 roots from the previous 7,539 admitted rehearsal rows (4,514 families, 4,484 components). The primary legal-choice filter requires at least two moves. Available primary cell row counts are high ordinary 224/387, low ordinary 290/444, low bonus 249/463 and low capture 411/316 for actors 0/1. Each cell's matching order is `(config.digest(SALT + raw_state_key), raw_state_key)` with `SALT=neurodiag-training-source-panel/20261102/v1/`. A recursive distinct-component matching fills 32 slots/cell; selected families and components are globally unique. No endpoint value or model error is read for matching.

All 28 clean complete H8/H10 source positions and all 48 ordinary self-play choice-zero records are secondary cohorts. The former are high ordinary 8/18 and low ordinary 1/1 by actor. The latter represent 24 starts, high 6/6 and low 5/7 by actor, with two separate outcomes each. Earlier joint self-play support is inventory-only. These source groups are not a newly balanced evaluation sample or 332 independent observations.

## Typed records and forward units

Every selected metadata row carries exact `state`, `state_key`, `family`, `component`, `quotient`, `actor`, `stratum`, `historical_role`, source key/hash, target references and its independently selected feature reference. Teacher references are journal/table/raw-key/item-SHA/requested-depth records. Packaging verifies requested H8/H10, exact original root linkage, complete legal action-Q support, actor-aware max/min target and full best ties. Approximate heuristic targets may be odd integers. Terminal targets instead bind the exact saved choice-zero decision, complete terminal game hash/family, final stores and even integer margin. They are individual control-policy returns, not solved game values.

Scalar target types are `approximate_H8_root_margin`, `approximate_H10_root_margin` and `observed_control_selfplay_terminal_margin`. Each record has a unique ID, raw state key, actor/family/cohort/stratum, original role/component, `target_player0`, `panel_row_sha256`, target-source evidence and feature-origin evidence. H8/H10 targets retain two records at the same source state; self-play retains both game IDs and outcomes separately.

The forward-unit key is the canonical digest of `{state_key, features:{x,d,r}}`. Its full payload is exact raw state/features, sorted scalar `records`, and deduplicated feature origins. Expected packaging is 332 source records, 360 scalar targets and 308 distinct raw-state/feature units. Primary, paired and self-play raw states are disjoint in this selected support. A repeated raw state must not acquire conflicting vectors or duplicate forwards.

The package preserves all features/targets/provenance so resume/complete readers do not reload target bodies or recompute features. Validation establishes declared source and metadata consistency; numerical model conformance and exact resolved-target truth are independently certified against the immutable physical package. Structural checks alone are not a replacement for that certificate.

## Feature sources and exploration disclosure

Primary roots use `build/ordinary-value-rows.json` rehearsal cached features; ordinary returns use the exact accepted `sp_rows.features`. Paired cached features come from eligible training projections in ordinary/value-pilot rows. SQL extracts only `.cached_features`, `.state`, `.state_key` and `.family` for the exact frozen path/group/index, keeping feature provenance separate from that cached row's own target. Each origin retains the physical file hash, cached projection hash and normalized `{x,d,r}` hash.

All paired states are checked by the frozen literal encoder: 15 compare against their existing cache at `1e-12`, and 13 missing vectors are generated. Cached values remain the original values. The package records the encoder SHA, generated raw keys, each comparison's exact feature hashes/max difference and counts. No Native, implicit pass, raw-state transform or quotient feature substitution is used.

An exploratory schema probe before formal selection parsed three training target-containing row bodies and printed field names, not values. Its exact script, field-only output and row/source identities are retained in `build/neurodiag-prefreeze/`. Targets were not ranking inputs. Formal inventory accesses label tables only through keys/hashes; the authorizer test rejects label/reference/attempt body access during that pass. Accordingly this is metadata-selected historical training data, not a claim of zero earlier body access or unseen holdout evidence.

## Source-bound checks and completion

The four `NeurodiagDataAuthor` methods cover target-body-denied inventory and component matching; exact typed target sources and cache-only input loads; forward deduplication and individual return/horizon estimands; and rehashed origin corruption, missing preflight, interrupted batch resume, uncertified refusal and durable completed-byte stability. Proof is `build/neurodiag-data-author.json`; only actually executed method IDs with current source/input pins count. Formal execution follows complete source freeze and root-controlled input packaging.

The independent audit checks eligibility, actual targets/features/forwards and final certified numerical cache separately. Production uses 16-unit atomic FULL/WAL batches; source-frozen owner/recovery fixtures use first48 units/three batches. Committed prefixes are never forwarded again; uncommitted interrupted batches may repeat. Only current independent production2 plus `build/neurodiag-audit/observation-witness.json` permits public completed access. Its pinned cache and summary are read without encoder/model/gradient/SVD calls. Missing required source/cache/certificate refuses; only the final report is repairable from certified persisted evidence.
