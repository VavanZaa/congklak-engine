# Neural-engine work after the root178 diagnosis

This stage freezes both model exports and the policy. It diagnoses existing teacher evidence; it does not train, generate new games, change a sampler or promote a model.

The next engineering priority should be the compact neural value/PUCT/self-play loop. Repeated retrospective weighting changes have not established a reliable admission rule. Stop that branch after explaining the present failures. Neural search is a promising direction for this project, but existing experiments do not demonstrate that it is more stable or stronger than both CPU baselines. H_v1 remains the default and the refined policy/control model remains the learned reference.

## What the saved experiments establish

The compact policy/search experiment improved policy teacher regret from 8.347 to 2.923 seeds and optimal-set accuracy from 50.29% to 64.72%, while value MAE increased. Its refined PUCT profile still failed the predeclared both-baseline strength gate. The later small self-play update changed paired margins by +0.25 seed against H_v1 and zero against H8 relay, with intervals including zero. The subsequent value-only pilot changed the paired H_v1 margin by -0.6667 seed and H10 validation MAE from 9.59909 to 9.63205. These are consumed development results, not independent release estimates. See QUALITY_RESULTS.md, SELFPLAY_PILOT_RESULTS.md and ORDINARY_VALUE_RESULTS.md.

Root178 and the capture cases concern finite-horizon teacher estimates. They are neither model-forward results nor proof that a neural network regressed. A stable root value can conceal a best-action reversal; changing alternative scores can leave the selected move intact. The next neural evaluation must retain both value error and action regret, rather than optimizing aggregate MAE alone.

## First bounded neural experiment to specify next

1. First diagnose eligible existing-data targets and the compact value path in a separately declared next stage: distinguish target inconsistency and noisy control-policy returns from fixed-feature representability, output saturation, gradient scale and optimization fit. These measurements require model forwards or gradients and do not run in the current stage. Preserve the exact-endgame behavior and current learned reference. Finite-horizon teacher margin, completed-policy return and minimax value are different objectives; retain their identities.
2. Audit optimizer eligibility before selecting targets. Apply the full accumulated reservation and family/quotient exclusions, including the consumed qstability panel and this diagnostic. Existing legacy trainers do not automatically enforce those overlays. Retain provenance and the current uniform/balanced sampler as a control; do not apply either rejected stability rule or fit a replacement from these cases.
3. Use those diagnostics to predeclare one small value-path treatment against the frozen control, with a fixed final checkpoint, optimizer/draw budget, loss/normalization, stratum coverage and stopping criteria before fresh outcomes. Do not repeat a 65-parameter head-only pilot without a new mechanism, or assume that added capacity fixes target errors. Preserve the policy outputs explicitly: changing a shared trunk changes them even if policy-head tensors are frozen; retain the frozen policy path if a separate value path is tested. Any architecture change needs its own checked export/inference contract. In-sample fit alone does not establish playing strength. Use admitted existing data first. Add distinct starts only for documented coverage deficits; add rollouts only to study policy-return uncertainty. No new corpus size or larger network is justified by this diagnostic alone.
4. Validate native CPU and batched GPU inference numerically for the actual exports. Separate feature extraction, queue delay, batch throughput and whole-decision latency. Keep search settings constant in the first value comparison and retain fixed-simulation diagnostics alongside equal-time results. Hardware availability is not evidence that GPU search is faster.
5. Run paired-seat equal-time games against both H_v1 and the frozen H8 relay CPU engine, with the existing K<=4 exact guard and ordinary/bonus/capture diagnostics. Predeclare fresh eligible evaluation families, effect metric, uncertainty and fallback accounting; existing consumed cases are regression diagnostics. Freeze a candidate before any sealed release evaluation.
6. Check physical process interruption during self-play publication, training checkpoints and evaluation decisions. Retain committed prefixes, optimizer/RNG state, full model/source identities and bounded resource telemetry. Promote only on the declared strength and regression criteria; otherwise retain the control.

This is a proposed next experiment, not authorization to begin it in the current existing-data stage. Final product work still includes measured strength/generalization, versioned exact-memory integration, a unified analyzer interface, clean-machine packaging, resource limits and rollback. Neural improvements do not establish a solved game or remove those requirements.
